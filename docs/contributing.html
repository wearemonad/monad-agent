Contributing to Monad

Thanks for helping. Bug reports, fixes, skills and connectors are all welcome.

Before you start

  • For anything bigger than a small fix, open an issue first so we can agree on the approach before you invest time.
  • Security problems: please don't open a public issue — see security.html.
  • By contributing, you agree that your contribution is licensed under the Apache License 2.0.

Development setup

macOS 14+ on Apple Silicon, Bun 1.3+, Xcode Command Line Tools, and Claude Code logged in (or an Anthropic API key).

git clone https://github.com/wearemonad/monad-agent.git
cd monad-agent/app
bun install
bun run dev          # renderer hot reload + bun-side --watch

Google features need your own OAuth client in a source build — see google-oauth.html.

Careful with --watch: the dev app runs against your real workspace registry (~/Library/Application Support/Monad/). Bun-side changes hot-reload instantly, so a workspace migration you're writing runs on your real workspaces the moment you save it. Use a throwaway workspace while working on migrations, the scheduler or ingest. Scheduled jobs in a real workspace may also fire paid model runs.

Checks

CI runs these on every pull request; please run them locally first:

bun run lint                     # repo root — Biome lint + format check
cd app && bun run typecheck      # tsc --noEmit
cd app && bun test src           # unit tests

bun run lint:fix at the repo root applies safe fixes and formatting.

Conventions

  • Bun everywhere — bun, bun test, bunx; no Node-only tooling. New dependencies respect the one-day minimumReleaseAge in bunfig.toml.
  • Process boundary — the webview never touches the SDK or the filesystem. New capabilities go in app/src/bun/ behind an RPC defined in app/src/shared/ipc.ts.
  • Synchronous fs in services — app/src/bun/ deliberately uses synchronous node:fs; keep that layer consistent.
  • Validate tool inputs before calling external APIs, with error messages the model can act on. A malformed tool input is our bug, not the user's.
  • Safety defaults — the agent never sends email, background runs never get wider permissions than interactive ones, and anything that writes to knowledge/ goes through the review queue.
  • Tests sit next to the code (Foo.ts → Foo.test.ts). Fix bugs test-first where practical.
  • UI components in components/ui/ come from shadcn and are regenerated by it — compose them rather than editing them.
  • Lint suppressions need a reason: // biome-ignore lint/<rule>: why.

Pull requests

  • Keep each PR to one change, with a description of what it changes and how you verified it.
  • UI changes: include a screenshot or short recording.
  • Don't bump versions or edit release files — maintainers do that when they release.
